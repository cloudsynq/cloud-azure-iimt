Section 01

What is a Virtual Network (VNet)?

An Azure Virtual Network (VNet) is your own private, isolated network inside Azure — just like a traditional on-premises LAN, but in the cloud. All Azure resources (VMs, databases, etc.) that need to talk to each other must be placed inside a VNet.

On-Premises Network

  • Physical routers & switches
  • You manage all hardware
  • Fixed capacity
  • Hard to scale quickly

Azure VNet

  • Software-defined networking
  • Azure manages infrastructure
  • Elastic, scale instantly
  • Global reach via peering

Key VNet Properties

  • Region-scoped: A VNet lives in one Azure region. Use VNet Peering to connect VNets across regions.
  • Subscription-scoped: Each VNet belongs to one subscription.
  • Address space: You define the IP range using CIDR notation (e.g., 10.0.0.0/16).
  • Free resource: Creating a VNet itself has no cost — you pay for gateways, IPs, and traffic.
Every VM you create in Azure is automatically placed inside a VNet. If you don't specify one, Azure uses the Default VNet.
Section 02

Subnets & Address Spaces

A VNet is divided into subnets — smaller IP ranges carved out of the VNet's address space. Subnets let you logically separate resources (e.g., web tier, app tier, database tier).

Address Space Planning

VNet ExampleCIDRTotal IPsUsable by Azure
VNet address space10.0.0.0/1665,536—
Web subnet10.0.1.0/24256251 (Azure reserves 5)
App subnet10.0.2.0/24256251
DB subnet10.0.3.0/24256251
Azure reserves 5 IPs in every subnet: .0 (network), .1 (default gateway), .2 & .3 (Azure DNS), .255 (broadcast). A /29 subnet only gives you 3 usable IPs.

Subnet Rules

  • Subnets cannot overlap within the same VNet.
  • Each subnet can have its own NSG and Route Table.
  • Special subnets: GatewaySubnet (for VPN/ExpressRoute gateways), AzureBastionSubnet (for Bastion Host) — these need specific names.
  • Minimum subnet size for most services: /28 (11 usable IPs after Azure reserves).
Section 03

IP Addressing in Azure

Private IP Addresses

Assigned from the subnet's address space. Used for communication within the VNet (or to on-premises via VPN/ExpressRoute). Never reachable from the internet directly.

  • Dynamic (default): Azure assigns an IP from the subnet. May change if the VM is stopped (deallocated).
  • Static: You pick a specific IP. Stays the same even after reboot. Use for DNS servers, domain controllers, firewalls.

Public IP Addresses

An optional resource that makes a VM reachable from the internet.

SKUAssignmentZone supportUse case
BasicDynamic or StaticNoDev/test, legacy
StandardStatic onlyYes (Zone-redundant)Production, Load Balancer
Standard SKU Public IP is recommended for production. Basic SKU is being retired.

Reserved IP Ranges (RFC 1918 — Private)

  • 10.0.0.0 – 10.255.255.255 (/8)
  • 172.16.0.0 – 172.31.255.255 (/12)
  • 192.168.0.0 – 192.168.255.255 (/16)
Use non-overlapping address spaces across your VNets from the start — once resources are deployed, changing the VNet address space is complex.
Section 04

Azure DNS

Azure DNS lets you host your DNS domains in Azure and resolves names to IP addresses. There are two types:

Public DNS Zones

  • For internet-facing domains (e.g., cloudsynq.shop)
  • Accessible from anywhere on the internet
  • You delegate your domain registrar's NS records to Azure
  • Records: A, AAAA, CNAME, MX, TXT, NS, SOA

Private DNS Zones

  • For internal name resolution within a VNet
  • Not accessible from the internet
  • E.g., vm1.internal.cloudsynq.local
  • Link to VNet with "auto-registration" to auto-add VM records

Default Azure DNS

By default, Azure provides DNS resolution at 168.63.129.16 — VMs can resolve each other by hostname within the same VNet automatically (using the VM's computer name).

Section 05

Network Security Groups (NSG)

An NSG is a virtual firewall that filters network traffic to and from Azure resources. It contains security rules — each rule specifies allow or deny based on source, destination, port, and protocol.

NSG Association

  • Subnet-level: Applies to all resources in the subnet (broader control).
  • NIC-level: Applies to a specific VM's network interface (fine-grained control).
  • Both can be applied simultaneously — both must allow traffic for it to pass.

NSG vs Azure Firewall: NSG is free, stateful (allows return traffic automatically), and works at L4 (port/protocol). Azure Firewall is a paid managed service with L7 filtering, FQDN rules, and threat intelligence.

Service Tags

Instead of memorizing Microsoft's IP ranges, use service tags like Internet VirtualNetwork AzureLoadBalancer Storage Sql — Azure keeps them updated automatically.

Section 06

Azure Bastion Host

Azure Bastion provides secure, browser-based RDP/SSH access to your VMs without exposing them to the public internet. You connect through the Azure Portal — no public IP needed on the VM.

Without Bastion (old way)

  • VM needs a Public IP
  • RDP port 3389 exposed to internet
  • Vulnerable to brute-force attacks
  • Requires VPN client for private access

With Azure Bastion

  • VM has no public IP needed
  • RDP/SSH over HTTPS (port 443)
  • Connection via Azure Portal browser
  • Full audit log in Azure Monitor

Setup Requirements

  • Create a dedicated subnet named exactly AzureBastionSubnet (minimum /26 size).
  • Deploy a Standard Public IP to the Bastion resource.
  • Bastion SKUs: Basic (RDP/SSH only) vs Standard (file transfer, tunneling, native client).
Azure Bastion is billed per hour. For dev/test environments, you can delete it when not in use and redeploy quickly.
