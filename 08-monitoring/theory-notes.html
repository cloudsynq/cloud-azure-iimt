Section 01

Azure Monitor Overview

Azure Monitor is the central monitoring platform for Azure. It collects, analyzes, and acts on telemetry data from Azure resources, on-premises infrastructure, and custom applications.

What Azure Monitor Collects

  • Metrics: Numeric time-series data (CPU%, disk IOPS, request rate)
  • Logs: Structured text records (activity logs, resource logs, custom logs)
  • Traces: Application distributed tracing (Application Insights)

What You Can Do

  • Visualize dashboards & workbooks
  • Alert on thresholds (email, SMS, webhook)
  • Auto-scale based on metrics
  • Diagnose and troubleshoot issues

Think of Azure Monitor as an umbrella service — it brings together Metrics, Log Analytics, Alerts, Application Insights, and Network Watcher under one roof.

Section 02

Metrics

Metrics are numeric values collected at regular intervals (usually every 1 minute). Every Azure resource automatically emits platform metrics — no configuration needed.

Common VM Metrics

MetricDescriptionUnit
Percentage CPUCPU utilization of the VM%
Network In/OutBytes received/sent on the NICBytes
Disk Read/Write BytesBytes read/written to diskBytes/sec
Available Memory BytesFree RAM (requires Azure Monitor Agent)Bytes
OS Disk IOPSDisk operations per secondCountPerSecond

Metrics Explorer

In the Azure Portal, go to any resource → Metrics to visualize metrics in charts. You can pin charts to Azure Dashboards for a custom monitoring view.

Platform metrics are retained for 93 days. For longer retention, export to a Log Analytics Workspace or Storage Account.
Section 03

Logs & Log Analytics

Logs contain structured records of events — more detail than metrics. Azure Monitor Logs stores them in a Log Analytics Workspace and uses the Kusto Query Language (KQL) to query them.

Types of Logs

Log TypeWhat it capturesWhere to enable
Activity LogSubscription-level operations (who did what, when)Automatic — 90 day retention
Resource Logs (Diagnostic)Resource-specific operations (VM start/stop, NSG flow)Diagnostic Settings on each resource
Azure AD LogsSign-ins, audit events, risky sign-insEntra ID → Diagnostic Settings
Guest OS LogsWindows Event Log, Linux syslog from inside VMAzure Monitor Agent (AMA)

KQL Sample Queries

// Find all failed sign-ins in last 24 hours SigninLogs | where TimeGenerated > ago(24h) | where ResultType != "0" | project TimeGenerated, UserPrincipalName, IPAddress, ResultDescription // Top 10 VMs by CPU Perf | where ObjectName == "Processor" | summarize avg(CounterValue) by Computer | top 10 by avg_CounterValue desc
Log Analytics Workspace is a central repository. You can connect multiple Azure subscriptions and on-premises servers to the same workspace for unified querying.
Section 04

Alerts & Action Groups

Azure Alerts automatically notify you or trigger an action when a metric or log condition is met.

Alert Components

  • Alert Rule: Defines the condition (e.g., CPU% > 90 for 5 minutes).
  • Action Group: Defines what happens when the alert fires (email, SMS, webhook, Azure Function, Logic App, ITSM).
  • Alert State: New → Acknowledged → Resolved.

Alert Signal Types

Signal TypeExample
Metric AlertCPU% > 80% for 5 minutes on VM-Prod
Log Alert (KQL)Count of failed logins > 10 in 1 hour
Activity Log AlertAlert when any VM in subscription is deleted
Smart DetectionApplication Insights automatically detects anomalies
Action Groups are reusable — one Action Group can be used by multiple alert rules. Create one "On-Call Team" group and reuse it everywhere.
Section 05

Application Insights

Application Insights is an APM (Application Performance Monitoring) service — it monitors live web applications, tracks exceptions, measures response times, and provides distributed tracing.

  • SDK-based: Add a small SDK to your app code (Node.js, .NET, Java, Python, etc.).
  • Tracks: Page views, HTTP requests, dependencies (SQL, Redis, API calls), exceptions, custom events.
  • Live Metrics: Real-time stream of requests/failures as they happen.
  • Application Map: Visual dependency graph showing how your microservices connect.
  • Smart Detection: Auto-detects anomalies (slow response, failure rate spike).
Application Insights stores its data in a Log Analytics Workspace. You can query it with KQL alongside other logs.
Section 06

Network Watcher

Network Watcher provides network monitoring, diagnostic, and visualization tools for Azure virtual networks.

Key Tools

ToolPurpose
IP Flow VerifyCheck if traffic is allowed/denied by NSG rules between two IPs
Next HopFind out where traffic goes next from a VM (useful for route debugging)
Connection MonitorContinuous connectivity test between endpoints (latency, packet loss)
NSG Flow LogsLog all traffic allowed/denied by NSGs — stored in Storage Account
Packet CaptureCapture network packets to/from a VM for deep analysis
VPN TroubleshootDiagnose VPN Gateway connection issues
Enable NSG Flow Logs for all production NSGs. They feed into Traffic Analytics for a visual map of your network flows and threat detection.
