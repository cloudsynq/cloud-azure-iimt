Section 01

What is Azure Entra ID?

Azure Entra ID (formerly Azure Active Directory / Azure AD) is Microsoft's cloud-based Identity and Access Management (IAM) service. It manages who can sign in (authentication) and what they can access (authorization).

On-Premises Active Directory (AD DS)

  • Windows Server Active Directory
  • Manages computers, users, printers on a corporate network
  • Uses Kerberos / NTLM authentication
  • Domain-joined machines only
  • No built-in cloud/internet access

Azure Entra ID

  • Cloud-based identity service
  • Manages SaaS apps, Azure resources, Microsoft 365
  • Uses OAuth 2.0 / OpenID Connect / SAML
  • Any device, anywhere (internet-based)
  • Built for modern cloud workloads

Entra ID Tenants & Subscriptions

  • A Tenant is your organization's dedicated instance of Entra ID (e.g., contoso.onmicrosoft.com).
  • An Azure Subscription trusts exactly one Entra ID tenant for authentication.
  • One tenant can have multiple subscriptions; one subscription trusts one tenant.
Entra ID is NOT a replacement for Windows Server AD in a corporate LAN. They serve different purposes — use Azure AD Connect to sync them for hybrid environments.

Users & Groups

User Types

TypeDescriptionExample

Managed IdentityAuto-managed identity for Azure resources — no password managementVM accessing Key Vault

Group Types

Security Groups

  • Used for access control — assign permissions to the group, members inherit
  • Can have users, devices, service principals, other groups
  • Membership: Assigned (manual) or Dynamic (rule-based query)

Microsoft 365 Groups

  • Collaboration groups — includes shared mailbox, Teams, SharePoint
  • Users only (no devices)
  • Membership: Assigned or Dynamic

Dynamic Membership Rules

Instead of manually adding users to groups, you can write a rule — e.g., "add all users where Department = Sales". Azure automatically adds/removes members as user attributes change.

Dynamic groups require Entra ID P1 or P2 license.
Section 03

Azure AD Connect (Hybrid Identity)

Azure AD Connect is a tool installed on-premises that synchronizes user identities from Windows Server AD to Entra ID. This creates a hybrid identity — the same user account works both on-premises and in the cloud.

Synchronization Options

MethodHow it worksPassword location
Password Hash Sync (PHS)Hash of the password is synced to Entra IDBoth on-prem and cloud
Pass-through Auth (PTA)Authentication request forwarded to on-prem AD agentOn-premises only
Federation (ADFS)Separate identity provider (ADFS) handles all authenticationOn-premises (ADFS)
Password Hash Sync is the simplest and most resilient option — recommended by Microsoft. It also enables leaked credential detection.

Section 05

MFA & Conditional Access

Multi-Factor Authentication (MFA)

MFA requires users to provide two or more verification factors — something you know (password) + something you have (phone) + something you are (biometric).

  • Microsoft Authenticator app (push notification or TOTP)
  • SMS / phone call
  • FIDO2 security key (hardware key)
  • Windows Hello for Business (biometric)

Conditional Access

Conditional Access defines policies that grant or block access based on conditions — like who the user is, where they are, what device they use, and what app they're accessing.

Signal (Condition)Examples
User / GroupAll admins, or specific high-risk groups
LocationBlock access from outside India
Device complianceRequire Intune-managed device
App / ServiceRequire MFA only for Azure Portal access
Sign-in riskBlock sign-in if risk level = High
Conditional Access requires Entra ID P1 license (included in Microsoft 365 Business Premium).
Section 06

Identity Protection

Entra ID Protection uses machine learning to detect suspicious sign-in behaviors and risky users — then automatically responds.

  • Sign-in Risk: Suspicious sign-in detected — e.g., impossible travel (login from India and USA within 1 hour), anonymous IP, password spray attack.
  • User Risk: User credentials leaked on the dark web, or consistent risky behavior.
  • Risk-based Conditional Access: Auto-require MFA for medium risk; auto-block for high risk; auto-reset password for risky users.
Identity Protection requires Entra ID P2 license.
Section 07

Privileged Identity Management (PIM)

PIM provides just-in-time (JIT) privileged access — instead of permanently assigning Global Admin, users request elevation for a limited time (e.g., 1 hour) with approval and audit trail.

  • Roles are eligible (not active) by default.
  • User requests activation → approver approves → role is active for N hours.
  • Full audit log of who activated what role, when, and why.
  • Reduces the attack surface of persistent privileged accounts.
Use PIM for all admin roles — especially Global Admin, Subscription Owner, and User Access Administrator. This is an exam and real-world best practice.
