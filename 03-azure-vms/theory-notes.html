Section 01

VM Sizes & Series

Azure VMs come in many sizes, grouped into series based on their purpose. You choose the series based on your workload type — don't just pick the cheapest; match the right type to your need.

B / D / E series

General Purpose

Balanced CPU & RAM. Good for web servers, dev environments, small databases.

F / FX series

Compute Optimized

High CPU-to-RAM ratio. Best for media transcoding, batch processing, gaming servers.

E / M / G series

Memory Optimized

High RAM. Best for in-memory databases (SAP HANA, SQL Server), caching.

L series

Storage Optimized

High disk throughput & IOPS. Best for big data, NoSQL, data warehousing.

N series

GPU

NVIDIA GPU. Best for AI/ML training, 3D rendering, visualization.

Section 02

VM Images

A VM Image is the template used to create the OS disk of your VM. It includes the operating system and sometimes pre-installed software.

Types of Images

  • Azure Marketplace — official images from Microsoft and third-party publishers: Windows Server 2022, Ubuntu 22.04, Red Hat, CentOS, SQL Server on Windows, etc.
  • Custom Image — you create a VM, install your software, then capture it as a "golden image" to deploy more VMs from
  • Azure Compute Gallery (formerly Shared Image Gallery) — store and share custom images across subscriptions and regions

Image URN Format

When using CLI, images are referenced by a URN: Publisher:Offer:SKU:Version

OSImage URN
Ubuntu 22.04 LTSCanonical:0001-com-ubuntu-server-jammy:22_04-lts:latest
Windows Server 2022MicrosoftWindowsServer:WindowsServer:2022-Datacenter:latest

For Students
Stick to Ubuntu 22.04 LTS for lab work — it's free, well-documented, and the most common choice for Linux servers on Azure. Windows Server VMs use more RAM and cost more.
Section 03

VM Disks

Every Azure VM has at least one disk. Understanding disk types helps you choose the right balance of performance and cost.

Types of Disks by Role

OS Disk

Contains the operating system. Created from the VM image. Max 4 TB. Cannot be detached from a running VM.

Data Disk

Additional disk for your data. Can attach/detach while VM is running. Multiple allowed per VM.

Temp Disk

Not persistent. Data lost on VM reboot/stop. Used for page file, swap file. Do NOT store important data here.

Disk Performance Tiers (Storage Types)

TierTypeIOPSLatencyBest for
Standard HDDMagneticUp to 500~10msDev/test, non-critical workloads
Standard SSDSSDUp to 6,000~4msLight production, web servers
Premium SSDSSDUp to 20,000<1msProduction databases, I/O-heavy apps
Ultra DiskSSDUp to 160,000<1msMission-critical SAP HANA, SQL
Temp Disk Warning
The temporary disk (usually /dev/sdb on Linux, D: on Windows) is physically attached to the VM host and is wiped on every VM stop/restart. Never put application data, database files, or SSH keys on the temp disk.
Section 04

VM Networking

A VM is always connected to a Virtual Network (VNet). Understanding the networking components is essential for troubleshooting connectivity.

Network Components for a VM

ComponentWhat it isNotes
Virtual Network (VNet)Your private network in Azure — like your own LAN in the cloudVMs in the same VNet can talk to each other by private IP
SubnetA segment within the VNet — used to organize resourcesVMs must be placed in a subnet
Network Interface Card (NIC)The VM's network adapterEach NIC has a private IP; can optionally have a public IP attached
Public IP AddressInternet-accessible IP for the VMOptional. Dynamic IPs change on restart; use Static if needed
Network Security Group (NSG)Firewall rules — allow or deny trafficCan be attached to a Subnet or a NIC

NSG Rules — Allow/Deny Traffic

NSG rules have a priority (100–4096, lower = higher priority), direction (inbound/outbound), protocol (TCP/UDP/Any), port range, and action (Allow/Deny).

PortProtocolPurposeOS
22TCPSSH — connect to Linux VM terminalLinux
3389TCPRDP — Remote Desktop to Windows VMWindows
80TCPHTTP — web trafficBoth
443TCPHTTPS — secure web trafficBoth
Security Best Practice
Never open port 22 (SSH) or 3389 (RDP) to the entire internet (0.0.0.0/0) in production. Restrict to your IP or use Azure Bastion for secure browser-based access — no public IP needed on the VM.
Section 05

Connecting to Virtual Machines

Linux VMs — SSH

Connect using an SSH key pair (recommended) or password. Azure generates or you upload a public key. The private key stays on your machine.

# Connect to Linux VM (replace with your IP and username)
ssh -i ~/.ssh/id_rsa azureuser@<public-ip-address>

Windows VMs — RDP

Download the RDP file from the Azure portal, open it in Remote Desktop Connection, and enter your username/password.

Azure Bastion — No Public IP Needed

Azure Bastion is a fully managed PaaS service that lets you connect to VMs securely from the browser, over TLS (port 443). The VM does NOT need a public IP or open SSH/RDP ports.

Section 06

Availability Options

A single VM can fail due to hardware issues, maintenance, or data center outages. Azure offers three options to improve availability:

Availability Set

Spreads VMs across Fault Domains (separate hardware racks) and Update Domains (patched at different times). Protects against hardware failure and maintenance downtime.

SLA: 99.95% uptime guaranteed.

Availability Zones

Spreads VMs across physically separate data centers (zones) within the same region. Each zone has independent power, cooling, networking.

SLA: 99.99% uptime guaranteed.

VM Scale Sets

Automatically deploy and scale a group of identical VMs. Scale out when load increases, scale in when load drops. Load balancer distributes traffic.

Best for auto-scaling web tiers.

Analogy
Availability Set = eggs in different rows of the same fridge shelf. Availability Zones = eggs in different fridges in different buildings. Scale Sets = a farm that automatically lays more eggs when demand increases.
Section 07

VM Extensions

VM Extensions are small scripts or applications that automate configuration tasks on VMs after they're deployed. No SSH or RDP needed — Azure runs them for you.

Common Extensions

ExtensionWhat it does
Custom Script ExtensionRuns a bash/PowerShell script on the VM. Use it to install software, configure services.
Azure Monitor AgentCollects logs and metrics from the VM and sends to Azure Monitor / Log Analytics.
Desired State Configuration (DSC)Keeps VM config consistent with a PowerShell DSC script — self-heals if config drifts.
Antimalware ExtensionRuns Microsoft Antimalware on Windows VMs — real-time protection.
Custom Script Extension Example
To install Nginx on an Ubuntu VM: upload a shell script to a Storage Account, then run the Custom Script Extension pointing to it. The VM will download and execute it automatically — no SSH session needed.
Section 08

VM Pricing Models

Azure offers multiple pricing options for VMs. Choosing the right model can reduce your bill by up to 90%.

PAY-AS-YOU-GO

On-Demand

Pay by the hour/second. No commitment. Most expensive but most flexible.

Best for: dev, testing, unpredictable workloads.

RESERVED

Reserved Instances

Commit to 1 or 3 years. Get up to 72% discount vs. on-demand.

Best for: stable, predictable workloads.

SPOT

Spot VMs

Use Azure's unused capacity at up to 90% discount. Can be evicted (stopped) with 30s notice when Azure needs the capacity back.

Best for: batch jobs, fault-tolerant workloads.

HYBRID BENEFIT

Azure Hybrid Benefit

If you have existing on-prem Windows Server or SQL Server licenses, use them on Azure. Saves up to 40% more on top of reserved pricing.

Free Tier for Students
Azure Free Account gives 750 hours/month of B1s VM free for 12 months. That's one VM running 24/7 for the entire year — plenty for lab work. Sign up at azure.microsoft.com/free/students.
Section 09

Summary — Key Points

VM Series

B/D = general purpose · F = compute · E/M = memory · L = storage · N = GPU

Disks

OS disk (boot), Data disk (persistent), Temp disk (LOST on reboot). HDD → SSD → Premium → Ultra

Networking

VNet + Subnet + NIC + NSG. Public IP optional. NSG = firewall (port 22/3389).

Bastion

Browser-based SSH/RDP. No public IP needed. Highest security.

Availability

Set (99.95%) → Zones (99.99%) → Scale Sets (auto-scale)

Pricing

On-demand > Reserved (72% off) > Spot (90% off). Match to workload stability.
