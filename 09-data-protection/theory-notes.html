Section 01

Data Replication Types

Azure Storage replicates your data to protect against hardware failures. The replication option you choose determines how many copies exist and where they are stored.

LRS

Locally Redundant Storage — 3 copies in 1 datacenter

ZRS

Zone Redundant — 3 copies across 3 Availability Zones in 1 region

GRS

Geo-Redundant — 6 copies: 3 primary region + 3 secondary region

RA-GRS

Read-Access GRS — GRS + read access to secondary region

TypeCopiesRegionsAvailability SLACost

For production workloads, use ZRS (single region, zone resilient) or GRS/GZRS (multi-region DR). LRS is only for dev/test or data that can be recreated.
Section 02

Recovery Services Vault

A Recovery Services Vault is an Azure storage container that holds backup data and recovery points for Azure VMs, SQL databases, Azure Files, and on-premises servers.

  • Must be in the same region as the resources being backed up.
  • Storage replication: LRS (default) or GRS (recommended for production DR).
  • Soft Delete: Protects backup data for 14 days after deletion (enabled by default).
  • One vault can protect resources from multiple subscriptions (with proper permissions).
Create a separate vault per region, per business unit. Mixing all backups in one vault makes role-based access harder to manage.
Section 03

Azure Backup

Azure Backup is Microsoft's cloud-based backup service. It protects on-premises machines, Azure VMs, SQL databases, SAP HANA, Azure Files, and more — all managed through Recovery Services Vault.

Backup Policy

A Backup Policy defines when backups run and how long recovery points are kept.

Policy SettingOptionsExample
Backup frequencyDaily, Weekly, Multiple times/dayDaily at 2:00 AM
Daily retention7–9999 days30 days
Weekly retentionOptionalKeep Sunday backups for 12 weeks
Monthly retentionOptionalKeep first-of-month for 12 months
Yearly retentionOptionalKeep Jan 1st backup for 5 years
Azure Backup uses the GRS replication by default for vault storage — backups are replicated to a paired region automatically.
Section 04

VM Backup & Restore

Azure Backup can back up the entire Azure VM — all OS disks and data disks — as application-consistent snapshots.

How VM Backup Works

  1. Backup job triggers at the scheduled time.
  2. Azure Backup Extension on the VM takes an application-consistent snapshot (using VSS on Windows).
  3. Snapshot is transferred incrementally to the Recovery Services Vault.
  4. Recovery point is created (Full, Incremental, or Differential).

Restore Options

Restore TypeWhat it doesUse case
Create new VMRestore to a brand new VMFull DR recovery
Restore disksRestore managed disks, then attach to any VMFlexible recovery
Replace existing diskSwap the OS/data disk on the existing VMFix corrupted disk
File RecoveryMount recovery point as a drive, browse and copy individual filesRecover single files
The first backup is a full backup; subsequent backups are incremental (only changed blocks are transferred). This saves cost and time.
Section 05

On-Premises Backup: MARS Agent

The Microsoft Azure Recovery Services (MARS) Agent is a small software agent installed on on-premises Windows servers or VMs. It backs up files, folders, and system state directly to a Recovery Services Vault — over the internet.

MARS Agent Limitations

  • Windows only (no Linux)
  • Files, folders, and system state only (not full VM image)
  • No application-consistent backup for SQL/Exchange
  • Requires internet or ExpressRoute to Azure

MARS Agent Advantages

  • No additional infrastructure needed
  • Simple setup (download, register, schedule)
  • Up to 3 backups per day
  • Supports compression and encryption

Other On-Premises Backup Options

  • Azure Backup Server (MABS): Windows server app that backs up Hyper-V VMs, SQL Server, SharePoint, Exchange — application-consistent. Free (no separate license).
  • DPM (Data Protection Manager): Microsoft System Center product — same capabilities as MABS but requires System Center license.
Section 06

Azure Site Recovery (ASR)

Azure Site Recovery provides disaster recovery (DR) by continuously replicating VMs to a secondary Azure region. If the primary region fails, you can failover in minutes.

  • Replicates Azure VMs, on-premises Hyper-V VMs, VMware VMs.
  • RPO (Recovery Point Objective): as low as 30 seconds.
  • RTO (Recovery Time Objective): typically under 2 hours.
  • Test failover: Run a DR drill without impacting production.
  • Failback: After the primary region recovers, replicate back and failback.
Use ASR for tier-1 applications that cannot tolerate datacenter outages. For less critical apps, Azure Backup (restore to new VM) is more cost-effective.
