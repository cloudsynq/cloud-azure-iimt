Section 01

App Service Plans

An App Service Plan defines the compute resources (CPU, RAM, storage) allocated for your web apps. Think of it as the "server" — multiple apps can share one plan.

TierPlanvCPU/RAMCustom Domain/SSLAuto-scale
Free/SharedF1, D1SharedNoNo
BasicB1, B2, B31–4 vCPU / 1.75–7 GBYesNo (manual)
StandardS1, S2, S31–4 vCPU / 1.75–7 GBYesYes (10 instances)
Premium v3P1v3–P3v32–8 vCPU / 8–32 GBYesYes (30 instances)
Isolated v2I1v2–I6v22–32 vCPUYesYes (100 instances)
Free (F1) tier is great for learning — 60 CPU minutes/day, 1 GB RAM, but no custom domain or SLA. For production, use Standard or Premium.
Section 02

Azure App Service (Web Apps)

Azure App Service is a fully managed PaaS platform for hosting web applications, REST APIs, and mobile backends. You deploy code — Azure handles OS, runtime, scaling, and patching.

Supported Runtimes

Languages & Frameworks

  • .NET / .NET Core
  • Node.js
  • Python, Ruby, PHP
  • Java (Spring Boot, Tomcat)
  • Custom Docker containers

Key Features

  • Built-in CI/CD (GitHub, Azure DevOps)
  • Deployment slots (staging → production swap)
  • Custom domains & free SSL
  • Auto-scaling (Standard tier+)
  • WebJobs for background tasks

Deployment Slots

Deployment slots are live environments (staging, QA) separate from production. You can deploy to staging, test, then do a zero-downtime swap — staging becomes production instantly.

Enable "Auto Swap" to automatically swap staging to production after a successful deployment — great for CI/CD pipelines.
Section 03

Azure SQL Database

Azure SQL Database is a fully managed, cloud-based relational database built on Microsoft SQL Server. No server patching, no OS management — just write SQL.

Deployment OptionDescriptionUse Case
Single DatabaseIsolated database with its own resourcesIndividual app database
Elastic PoolShare resources across multiple databasesSaaS apps with variable load
Managed InstanceNear 100% SQL Server compatibility, in a VNetLift-and-shift of on-prem SQL

Service Tiers

  • General Purpose: Balanced compute/storage — most workloads.
  • Business Critical: High IOPS, in-memory OLTP, read replicas.
  • Hyperscale: Up to 100 TB, fast backups and restores.
Azure SQL Database automatically takes backups — full weekly, differential daily, transaction logs every 5–12 minutes. Point-in-time restore to any moment in the last 7–35 days.
Section 04

Containers & Docker

A container packages an application and all its dependencies (libraries, config) into a portable, lightweight image. It runs identically on any machine — developer laptop, test server, or Azure cloud.

VM vs Container

  • VM: Full OS per instance (GBs of overhead)
  • Container: Shares host OS kernel (MBs of overhead)
  • VM: Minutes to start
  • Container: Seconds to start

Docker Concepts

  • Dockerfile: Recipe to build an image
  • Image: Read-only template
  • Container: Running instance of an image
  • Registry: Store and share images (Docker Hub, ACR)
# Sample Dockerfile for a Node.js app FROM node:18-alpine WORKDIR /app COPY package*.json ./ RUN npm install COPY . . EXPOSE 3000 CMD ["node", "server.js"]
Section 05

Azure Container Registry (ACR)

ACR is Azure's private Docker registry — store, manage, and deploy your container images securely within Azure. No images are public unless you choose.

  • Integrates with AKS, App Service, and Azure Container Instances.
  • Geo-replication: Replicate images to multiple regions for low-latency pulls.
  • ACR Tasks: Build images in the cloud without Docker installed locally.
  • Three SKUs: Basic, Standard, Premium (Premium supports geo-replication and private endpoints).
az acr build --registry myregistry --image myapp:v1 .
Section 06

Azure Kubernetes Service (AKS)

Kubernetes (K8s) is an open-source system for automating deployment, scaling, and management of containerized applications. AKS is Azure's managed Kubernetes — Microsoft manages the control plane (free), you manage the worker nodes.

Key Kubernetes Concepts

ConceptDescription
PodSmallest deployable unit — one or more containers sharing network and storage
DeploymentManages a set of identical Pods; handles rolling updates and rollbacks
ServiceStable IP/DNS to expose Pods (ClusterIP, NodePort, LoadBalancer)
NodeVM that runs Pods (AKS: Azure VMs)
Node PoolGroup of nodes with the same VM size
NamespaceLogical isolation within a cluster (dev, staging, prod)
In AKS, the control plane (API server, etcd, scheduler) is fully managed by Microsoft at no cost. You only pay for the worker nodes (Azure VMs).
Section 07

Azure Functions (Serverless)

Azure Functions lets you run small pieces of code (functions) without managing any server. You write the code; Azure handles scaling, patching, and infrastructure. You only pay for execution time.

  • Triggers: HTTP, Timer (CRON), Blob Storage upload, Queue message, Event Hub, Service Bus.
  • Supported languages: C#, JavaScript, Python, Java, PowerShell, TypeScript.
  • Consumption plan: Scale to zero (no cost when idle); auto-scale under load.
  • Premium plan: Pre-warmed instances (no cold start); VNet integration.
Use Azure Functions for event-driven, short-running tasks: image resizing on upload, sending notifications, processing queue messages. For long-running workflows, use Azure Logic Apps or Durable Functions.
