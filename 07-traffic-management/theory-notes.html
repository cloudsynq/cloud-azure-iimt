Load Balancing Overview

Load balancing distributes incoming traffic across multiple backend resources to ensure high availability, prevent overload, and achieve scalability. Azure provides four different load balancing services — each suited for different scenarios.

ServiceLayerScopeUse Case
Azure Load BalancerL4 (TCP/UDP)RegionalVM-level load balancing
Application GatewayL7 (HTTP/HTTPS)RegionalWeb apps, URL routing, WAF
Traffic ManagerDNS-basedGlobalMulti-region routing
Azure Front DoorL7 (HTTP/HTTPS)GlobalGlobal web apps, CDN, WAF
Section 02

Azure Load Balancer (L4)

Azure Load Balancer operates at Layer 4 (Transport layer) — it distributes TCP and UDP traffic across VMs. It does not inspect HTTP content — just ports and IPs.

Key Components

  • Frontend IP: The public or private IP that clients connect to.
  • Backend Pool: The VMs that receive traffic.
  • Health Probes: Periodically test if backend VMs are healthy (HTTP, HTTPS, TCP). Unhealthy VMs are removed automatically.
  • Load Balancing Rules: Map frontend port → backend port for a protocol.
  • NAT Rules: Forward specific ports to specific VMs (e.g., port 50001 → VM1:3389 for RDP).

Public Load Balancer

  • Has a public IP frontend
  • Distributes internet traffic to VMs
  • Provides outbound internet SNAT for VMs without public IPs

Internal Load Balancer

  • Has a private IP frontend
  • Distributes traffic between internal tiers (e.g., web → app)
  • Not reachable from internet

Section 03

VM Scale Sets (VMSS)

VM Scale Sets let you deploy and manage a group of identical VMs that auto-scale based on demand. When load increases, new VMs are added; when load drops, VMs are removed — automatically.

  • All VMs in a Scale Set are identical (same image, same size).
  • Supports up to 1,000 VMs (custom image) or 600 VMs (platform image).
  • Works with a Load Balancer or Application Gateway for traffic distribution.
  • Scaling policies: schedule-based or metric-based (CPU%, memory, custom metrics).

Scaling Policies

PolicyTriggerExample
ManualYou set instance countScale to 5 VMs for a launch event
Automatic (Metric-based)CPU/Memory thresholdAdd 1 VM when CPU > 70% for 5 min
Schedule-basedTime of day / weekScale up at 9 AM, down at 6 PM
Use Flexible Orchestration mode for VMSS (default in new deployments) — it supports mixing instance types and placing VMs in Availability Zones.
Section 04

Azure Traffic Manager

Traffic Manager is a DNS-based global load balancer. It does not proxy traffic — it returns a DNS response pointing the user to the best endpoint. Then the user connects directly to that endpoint.

Routing Methods

MethodHow it worksUse case
PriorityAlways route to primary; failover to secondary if primary is downActive/passive DR
WeightedRoute % of traffic to each endpoint (e.g., 80/20)Gradual rollout, A/B testing
PerformanceRoute to endpoint with lowest latency (closest to user)Global multi-region apps
GeographicRoute based on user's country/regionData residency compliance
MultivalueReturn all healthy endpoints in DNS responseClient-side load balancing
SubnetMap IP ranges to specific endpointsSpecific ISP or office routing
Traffic Manager monitors endpoint health via HTTP/HTTPS/TCP probes. Unhealthy endpoints are automatically excluded from DNS responses.
Section 05

Application Gateway (L7 Load Balancer)

Application Gateway is a Layer 7 (HTTP/HTTPS) load balancer. Unlike Azure Load Balancer, it understands HTTP content — enabling URL-based routing, cookie-based session affinity, SSL termination, and Web Application Firewall (WAF).

Key Features

  • URL-based routing: Route /images/* to image servers, /api/* to API servers.
  • SSL/TLS Termination: Decrypt HTTPS at the gateway, reducing backend load.
  • Cookie-based session affinity: Stick a user to the same backend VM.
  • Web Application Firewall (WAF): Protects against OWASP Top 10 (SQL injection, XSS, etc.).
  • Autoscaling: v2 SKU scales automatically based on traffic.
  • Rewrite rules: Modify HTTP request/response headers.

Azure Load Balancer

  • Layer 4 (TCP/UDP)
  • IP + port based routing only
  • No HTTP inspection
  • Lower cost

Application Gateway

  • Layer 7 (HTTP/HTTPS)
  • URL path routing
  • WAF, SSL termination
  • Higher cost
Section 06

Azure Firewall

Azure Firewall is a fully managed, stateful cloud-native firewall — deployed in a hub VNet to protect all connected spoke VNets and on-premises networks. More powerful than NSGs.

Azure Firewall vs NSG

FeatureNSGAzure Firewall
CostFree~$1/hr + data processed
FQDN filteringNoYes (block *.malware.com)
Threat intelligenceNoYes (Microsoft feed)
Centralized managementPer-subnet/NICOne policy, all VNets
L7 awarenessNoYes (HTTP/S, SQL, RDP)
DeploymentAttached to subnet/NICDeployed in dedicated subnet
Azure Firewall requires a dedicated subnet named AzureFirewallSubnet (minimum /26). Use Azure Firewall Manager to centrally manage policies across multiple firewalls.
