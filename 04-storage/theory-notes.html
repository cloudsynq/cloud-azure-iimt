01 · Introduction

What is Azure Storage?

Azure Storage is Microsoft Azure's cloud storage solution. It is a service that lets you store data in the cloud — files, images, videos, database tables, messages — and access them from anywhere in the world over the internet.

Simple Analogy
Think of Azure Storage as a big secure warehouse owned by Microsoft. You can store anything in this warehouse — files, photos, messages — and access them from your laptop, phone, or any application, from anywhere in the world, anytime.

Why Do We Need Cloud Storage?

  • Your laptop hard disk can crash — cloud storage survives hardware failure
  • You can access data from anywhere — not just from one computer
  • Multiple people and applications can use the same data at the same time
  • Azure automatically keeps multiple copies of your data (redundancy)
  • You only pay for what you use — no need to buy physical hard drives

Azure Storage has 4 Types

🗂️

Blob Storage

Store any type of file — images, videos, PDFs, backups. Like Google Drive.

📁

Azure Files

Shared network drive that multiple VMs can connect to. Like a company's shared folder.

📊

Azure Tables

Store structured data (like a table/spreadsheet) without a complex database setup.

📬

Queue Storage

Store messages between applications. Like a to-do list that apps process one by one.

02 · Foundation

Storage Account — The Foundation

Before you can use any type of Azure Storage, you must first create a Storage Account. A Storage Account is the container that holds all your storage services (Blob, Files, Tables, Queue) together.

Simple Analogy
A Storage Account is like a bank account. The bank account itself does not hold cash directly — inside it you have a savings account, a current account, a locker, etc. Similarly, the Storage Account contains your Blob Containers, File Shares, Tables, and Queues.

Key Properties of a Storage Account

The name must be globally unique across all of Azure — no two accounts in the world can have the same name. This is because it becomes part of the URL:

03 · Blob Storage

Azure Blob Storage

BLOB stands for Binary Large OBject. Blob Storage is used to store unstructured data — meaning any type of file that doesn't follow a fixed format.

Simple Analogy
Blob Storage is like Google Drive or Dropbox — but for your applications and websites. You upload any file (photo, video, PDF, zip, backup) and get a URL to access it. Your website can display images from Blob Storage directly.

What Can You Store in Blob?

  • Images and videos for websites
  • PDF documents and reports
  • Database backups and log files
  • Build artifacts in a DevOps pipeline
  • Machine learning datasets
  • Audio files, ZIP files — literally anything

Blob Storage Structure

LevelNameAnalogy
Top LevelStorage AccountThe bank account
Middle LevelContainerA folder inside Drive
Bottom LevelBlob (the actual file)A file inside the folder

Types of Blobs

Blob TypeBest ForExample
Block BlobMost files — images, videos, documentsphoto.jpg, report.pdf
Append BlobLog files (only add, never overwrite)app.log, error.log
Page BlobVM disk files (VHDs), frequent random read/writevm-disk.vhd

Container Access Levels

  • Private (default) — Only authorized users can access. Need authentication. Best for sensitive data.
  • Blob — Anyone with the URL can read blobs, but cannot list what's inside the container.
  • Container — Anyone can list all blobs inside and read them. Use for fully public data.
SAS Token — Temporary Access
If a container is Private but you want to share one file temporarily, use a SAS (Shared Access Signature) Token. It generates a special URL with an expiry time. After the time expires, the URL stops working.

Example: Share a file that expires in 2 hours for a client download.

AWS Equivalent

Azure Blob Storage = Amazon S3 (Simple Storage Service). Both are object storage services for storing any type of file.

04 · Azure File Storage

Azure File Storage

Azure File Storage provides fully managed network file shares in the cloud using the SMB (Server Message Block) protocol — the same protocol Windows uses for shared drives on a local network.

Simple Analogy
Azure File Storage is like a shared office folder on a company network. Every computer in the office can access the same folder (Z: drive). Azure File Storage does the same thing — but in the cloud. Multiple VMs and computers can connect to the same shared folder simultaneously.

Key Features

  • Uses SMB protocol — works with Windows, Linux, and macOS
  • Multiple VMs can mount the same file share at the same time
  • Works like a normal folder — copy, paste, move files just like on your computer
  • Can replace on-premises file servers (no need to maintain physical servers)
  • Accessible via Azure Portal, Storage Explorer, or command line

Blob Storage vs Azure Files — Key Difference

Blob StorageAzure Files
ProtocolHTTP/HTTPS (REST API)SMB (network drive)
Access StyleApplication downloads file via URLMounted as a drive letter (Z:\)
Use CaseWebsites, apps, backupsShared config files, multi-VM access
Simultaneous UsersMany (read via URL)Many (mounted as network drive)
AWS EquivalentAmazon S3Amazon EFS (Elastic File System)
Real World Use Case
A company has 5 web servers running the same application. The app needs a config file. Instead of copying the config file to each server manually, store it once in Azure File Storage and mount the share on all 5 servers. When you update the config file once, all 5 servers see the change immediately.

05 · Azure Tables

Azure Table Storage

Azure Table Storage is a NoSQL key-value store for storing structured data. It stores data in rows and columns (like a spreadsheet), but without the complexity of a full SQL database.

Simple Analogy
Think of Azure Tables as a giant Excel sheet stored in the cloud. Each row is an entity (like a student record), and each column is a property (Name, Age, Grade). You can store billions of rows and query them quickly using a key.

Key Concepts

TermMeaningAnalogy
TableA collection of entitiesAn Excel sheet
EntityA single recordA row in the sheet
PropertyA field/column in the entityA cell value in a row
Partition KeyGroups related entities together for fast queriesA category/section
Row KeyUnique ID within a partitionA roll number

When to Use Azure Tables?

  • Storing user profiles or preferences
  • Application configuration data
  • Session data for web apps
  • Log data with simple querying needs
  • When you need to store millions of records cheaply without a full SQL database
Azure Tables vs SQL Database
Azure Tables is NoSQL — it is faster and cheaper for simple data but cannot do complex JOINs like SQL. Use Azure Tables for simple key-value lookups. Use Azure SQL Database for complex relational data with multiple tables.

AWS Equivalent

Azure Table Storage ≈ Amazon DynamoDB — both are NoSQL key-value stores for semi-structured data.

06 · Queue Storage

Azure Queue Storage

Azure Queue Storage is a message queue service. It stores messages (small pieces of text or data) that one part of your application sends, and another part reads and processes later.

Simple Analogy
Imagine a restaurant kitchen order system. A waiter takes your order and puts a ticket on the kitchen counter (queue). The chef picks up tickets one by one and prepares the food. The waiter doesn't wait at the kitchen — they can go take more orders. This is exactly what Queue Storage does for applications.

Why Do We Need a Message Queue?

  • Decoupling — Part A of your app doesn't need to wait for Part B to finish. It just adds a message to the queue and moves on.
  • Load balancing — If too many requests come in, they wait in the queue. Workers process them at their own pace.
  • Reliability — If a worker crashes, the message stays in the queue and another worker picks it up.
  • Async processing — Handle background tasks (sending emails, resizing images, generating reports) without blocking the main app.

How Queue Works (Step by Step)

  1. User uploads a photo on a website
  2. Web app adds a message to the queue: "Resize photo X"
  3. Web app responds to user immediately: "Upload successful!"
  4. A background worker reads the message from the queue
  5. Worker resizes the photo and saves it
  6. Worker deletes the message from the queue (job done)
Key Facts
• Maximum message size: 64 KB
• Maximum queue size: 500 TB
• Message expiry (default): 7 days
• A message can be locked (invisible) while a worker processes it — if the worker fails, the lock expires and another worker gets the message

AWS Equivalent

Azure Queue Storage = Amazon SQS (Simple Queue Service) — both are managed message queue services for async communication between application components.

07 · Redundancy

Storage Redundancy Types

Azure automatically keeps multiple copies of your data to protect against hardware failures. The type of redundancy determines where and how many copies are kept.

Simple Analogy
Redundancy is like making photocopies of important documents. LRS = 3 copies in the same building. GRS = 3 copies in Delhi + 3 copies in Mumbai (in case Delhi floods). More copies = more safety = more cost.
LRS
Locally Redundant Storage

3 copies within one datacenter in one region. Cheapest option.

ZRS
Zone Redundant Storage

3 copies across 3 different Availability Zones in one region.

GRS
Geo-Redundant Storage

3 copies in primary region + 3 copies in a paired secondary region (e.g., India South).

GZRS
Geo-Zone Redundant

3 copies across zones in primary region + 3 copies in paired region. Maximum protection.

10 · Summary

Chapter Summary

Key Points to Remember

  • Azure Storage has 4 types: Blob, Files, Tables, Queue
  • A Storage Account must be created first — it holds all storage types
  • Storage Account name is globally unique and becomes part of the URL
  • Blob Storage = any file (images, videos, backups) — accessed via URL — like S3
  • Azure Files = shared network drive using SMB — like EFS
  • Azure Tables = NoSQL key-value store — like DynamoDB
  • Queue Storage = messages between apps (async) — like SQS
  • Access Tiers: Hot → Cool → Cold → Archive (cost vs access speed tradeoff)
  • SAS Token = temporary access URL for private blobs with expiry time
  • Redundancy: LRS (cheap) → ZRS → GRS → GZRS (most protected)
  • Deny-by-default: Blob containers are Private by default
