01 · Introduction

What is Azure Storage?

Azure Storage is Microsoft Azure's cloud storage solution. It lets you store data in the cloud and access it from anywhere in the world. Azure Storage is not one service — it is a family of services covering all three types of storage needs.

Simple Analogy
Think of Azure Storage as a big multi-storey warehouse owned by Microsoft. Floor 1 = file lockers (Blob). Floor 2 = shared office cabinets (Azure Files). Floor 3 = personal hard drives for computers (Managed Disks). You can use whichever floor you need.

Azure's 3 Storage Categories (Seen in Portal)

CategoryAzure ServiceWhen to UseAWS Equivalent
Object StorageBlob StorageFiles, images, videos, backups accessed via URLAmazon S3
Block StorageAzure Managed DisksVM's hard drive — OS disk and data disksAmazon EBS
File StorageAzure FilesShared network drive mounted by multiple VMsAmazon EFS
NoSQL StoreAzure TablesSimple key-value data — user preferences, IoT dataAmazon DynamoDB
Message QueueQueue StorageMessages between application components (async)Amazon SQS

Why Cloud Storage Over Physical Hard Drive?

  • Physical hard drives crash — cloud storage survives hardware failure automatically
  • Access from anywhere — not limited to one machine
  • Multiple apps and VMs can access the same data simultaneously
  • Azure keeps multiple copies automatically (redundancy)
  • Pay only for what you use — no upfront hardware cost
🏢 Real Company — Why Cloud Storage Matters

Hotstar (Disney+Hotstar) — India's biggest OTT platform — stores millions of video thumbnails, show posters, episode previews, and subtitle files in Azure Blob Storage. During IPL, they have 50+ million concurrent users. If they stored all this on physical servers, they would need a warehouse full of hard drives. With Azure, they pay per GB and scale instantly.

Paytm — Stores every user's KYC documents (Aadhaar scan, PAN card photo) in Blob Storage with encryption. These documents are accessed rarely (only during verification) so they use the Cool tier to save costs.

02 · Foundation

Storage Account — The Foundation

Before using Blob, Files, Tables, or Queue — you must first create a Storage Account. It is the container that holds all Azure Storage services together. Note: Managed Disks do NOT need a Storage Account — they are a separate resource.

Simple Analogy
A Storage Account is like a bank account. The bank account itself doesn't hold cash — inside it you have savings, current account, locker, etc. Similarly, the Storage Account holds your Blob Containers, File Shares, Tables, and Queues.

Key Properties

PropertyWhat It MeansExample
NameGlobally unique, all lowercase, 3–24 chars, no spaces or special charsiimt2026storage
RegionPhysical datacenter where data is storedCentral India
PerformanceStandard (HDD-backed, cheaper) or Premium (SSD-backed, faster)Standard
RedundancyHow many copies Azure keeps and whereLRS, GRS, ZRS
Access TierHot (frequent access) or Cool (infrequent, cheaper)Hot
Globally Unique Name — Why?
The Storage Account name becomes part of the public URL:
https://iimt2026storage.blob.core.windows.net

Since URLs are global, no two accounts anywhere in the world can share the same name. This is why names like "storage1" or "test" are always already taken.

🏢 Real Company — Storage Tiers in Action

HDFC Bank uses Azure Storage for all transaction records. Recent transactions (last 30 days) → Hot tier (customers access frequently for statements). Transactions older than 1 year → Cool tier (accessed occasionally for disputes). Transactions older than 7 years → Archive tier (only accessed for RBI audits — retrieved with hours of delay, but 90% cheaper storage cost).

03 · Object Storage

Azure Blob Storage

BLOB = Binary Large OBject. Blob Storage stores unstructured data — any type of file that doesn't follow a fixed format. It is Azure's object storage service and the most commonly used storage type.

Simple Analogy
Blob Storage is like Google Drive or Dropbox — but for your applications. You upload any file (photo, video, PDF, zip) and get a URL to access it. Your website can show images directly from Blob Storage via that URL.

Structure: Account → Container → Blob

LevelNameAnalogyExample
TopStorage AccountThe bankiimt2026storage
MiddleContainerA folder inside Drive/profile-photos
BottomBlob (actual file)A file in the foldersahil.jpg

Full URL of a blob: https://iimt2026storage.blob.core.windows.net/profile-photos/sahil.jpg

3 Types of Blobs

Blob TypeBest ForReal Example
Block BlobMost files — images, videos, documents, backupsphoto.jpg, report.pdf, backup.zip
Append BlobLog files — only append new data, never overwriteapp.log, access.log, error.log
Page BlobVM disk files (VHDs) — frequent random read/writevm-os-disk.vhd (used internally by Azure)

Container Access Levels

  • Private (default) — Need authentication to access. Use for sensitive data (KYC, bank statements).
  • Blob level — Anyone with the URL can read that specific file, but can't list all files in the container.
  • Container level — Anyone can list all files and read them. Use for fully public data (website images).
SAS Token — Temporary Access URL
If a container is Private but you want to share one file temporarily → use a SAS (Shared Access Signature) Token. It generates a special URL with an expiry time. After expiry, the URL automatically stops working.

Example: "Download your salary slip" link valid for 24 hours only.
🏢 Real Company Scenarios — Blob Storage

Zomato stores every restaurant's menu photos, banner images, and food images in Azure Blob Storage. When you open Zomato app, images load from Blob Storage via CDN (Content Delivery Network). They have millions of images. With Archive tier for old/inactive restaurant data, they save ~80% on storage costs for images that are no longer shown.

Swiggy uses Append Blobs for application logs. Every order event (placed, accepted, picked up, delivered) gets appended to a log file. These logs are never overwritten — only new lines are added. After 90 days, old logs move to Archive tier.

PolicyBazaar stores all insurance policy documents (PDFs) in Blob Storage with Private access. Each customer gets a SAS Token URL valid for 7 days to download their document after purchase.

AWS Equivalent

Azure Blob Storage = Amazon S3 — both are object storage services. S3 uses "buckets" instead of "containers" but the concept is identical.

04 · Block Storage — NEW TOPIC

Azure Managed Disks — Block Storage

Azure Managed Disks are virtual hard drives (VHDs) that attach directly to Azure Virtual Machines. When you create a VM, it needs a hard drive — that hard drive is a Managed Disk. This is Azure's block storage service.

They are called "Managed" because Microsoft handles everything behind the scenes — storage account creation, replication, snapshots, encryption. You just create a disk and attach it to a VM.

Simple Analogy
Think of a Managed Disk as the hard drive inside your laptop. Your laptop (VM) cannot work without a hard drive (Managed Disk). It is directly attached — not accessed over the internet like Blob Storage. It's fast, dedicated, and specific to that one machine.

3 Disk Roles on a VM

🖥️
OS Disk

Contains Windows/Linux OS. Every VM must have exactly one. Can't be detached while VM runs.

💽
Data Disk

For your database, app files, or extra storage. One VM can have multiple data disks (up to 32 TB each).

⚡
Temp Disk

Temporary scratch space. Fast but NOT persistent — data is lost when VM stops or restarts. Never store important data here.

Critical Warning — Temp Disk
The Temp disk (D: on Windows, /dev/sdb on Linux) is not reliable storage. It is physically on the host server, not replicated. If your VM is stopped, deallocated, or migrated — ALL data on the temp disk is permanently lost. Only use it for swap files, caches, or calculations.

5 Disk Types — Choose Based on Workload

ULTRA DISK

Ultra Disk

Up to 160,000 IOPS · Sub-ms latency

Highest performance available. Adjustable IOPS and throughput without detaching.

Use: Trading platforms, SAP HANA, high-frequency databases
PREMIUM SSD v2

Premium SSD v2

Up to 80,000 IOPS · Sub-ms latency

Flexible performance configuration. Better price than Ultra for most production workloads.

Use: Production databases, ERP systems, enterprise apps
PREMIUM SSD

Premium SSD

Up to 20,000 IOPS · Single-ms latency

Best price/performance for most production workloads. Most commonly used in enterprises.

Use: Production web servers, SQL Server, MySQL, MongoDB
STANDARD SSD

Standard SSD

Up to 6,000 IOPS · Low single-digit ms

Consistent performance for workloads that don't need high IOPS.

Use: Dev/test VMs, lightly used web servers, non-critical apps
STANDARD HDD

Standard HDD

Up to 2,000 IOPS · High latency OK

Cheapest option. Uses spinning hard disk. High latency acceptable.

Use: Dev/test, backups, non-critical batch processing

Key Features of Managed Disks

FeatureWhat It Does
SnapshotsPoint-in-time copy of a disk. Create before risky operations. If something breaks, restore from snapshot.
Server-Side Encryption (SSE)Data on disk is automatically encrypted at rest. On by default — no extra cost or action needed.
Disk ResizeIncrease disk size without data loss. Cannot decrease size (only increase allowed).
Disk BurstingStandard SSD and Premium SSD can burst to higher IOPS temporarily for peak loads.
Shared DisksSame disk attached to multiple VMs simultaneously (for clustered applications like SQL Server AlwaysOn).
ZRS DisksZone-Redundant Managed Disks — replicated across 3 availability zones. No data loss if one zone goes down.
🏢 Real Company Scenarios — Managed Disks

Zerodha (India's largest stock broker) runs its trading database on Azure VMs with Ultra Disks. During market hours (9:15 AM – 3:30 PM), thousands of trades per second are written. Ultra Disk gives sub-millisecond latency — even 5ms delay can mean a trade at a different price. They configure 100,000 IOPS during market hours and reduce at night to save money.

Wipro IT migrated 500+ on-premises servers to Azure VMs. Each VM got a Managed Disk. Dev/test servers got Standard SSD (cheap, consistent). Production SAP servers got Premium SSD. All disks have automatic encryption — zero compliance effort needed compared to managing physical encryption on-prem.

Apollo Hospitals stores medical imaging data (CT scans, MRI) on Data Disks (Premium SSD) attached to their imaging servers. They take daily snapshots before any system updates. If an update breaks something, they restore to yesterday's snapshot in under 10 minutes — critical for hospital operations.

Managed Disk vs Unmanaged Disk

Why "Managed" Matters
Before Managed Disks existed, disks were stored as VHD files inside a Storage Account (called Unmanaged Disks). You had to manually manage storage account limits, performance, and replication.

Managed Disks (2017 onwards) let Microsoft handle all of that automatically. Today, always use Managed Disks — Unmanaged Disks are deprecated and not recommended.

05 · File Storage (Expanded)

Azure Files — File Sharing Storage

Azure Files provides fully managed network file shares in the cloud. It replaces on-premises file servers completely. Multiple VMs, computers, and even on-premises servers can connect to the same shared folder simultaneously.

Simple Analogy
In your college computer lab, all computers share a common Z: drive — you save a file on one computer and access it on another. Azure Files does exactly this — but in the cloud. Any VM, any computer, anywhere in the world can mount the same folder as a drive letter.

2 Protocols Supported

ProtocolUsed ByPortWhen to Use
SMB (Server Message Block)Windows, Linux, macOS445Windows-based file shares, office shared drives, config files for Windows apps
NFS (Network File System)Linux / Unix only2049Linux-based applications, POSIX permissions needed, high-performance Linux workloads
SMB Port 445 Blocked?
Many ISPs (including Jio, Airtel) block port 445 for residential connections. If you try to mount Azure Files from your home laptop over the internet, it may fail. Solution: Use Azure VPN Gateway or access from an Azure VM (which has direct access).

Azure File Share Tiers

CoolHDDOnline backup, rarely accessed archivesLowest

Azure File Sync — Bridge Between On-Premises and Cloud

Azure File Sync is a powerful feature that syncs your on-premises Windows Server file folders with Azure Files automatically. It's like OneDrive but for your company's file servers.

What It DoesHow It Works
Files sync both waysChange a file on your office server → it appears in Azure. Change in Azure → it appears on office server.
Cloud TieringRarely used files are automatically moved to Azure, freeing up local disk space. They appear as "placeholder" files on the server.
Multiple offices3 offices in Delhi, Mumbai, Bangalore — all share the same Azure File Share. Changes in one office appear in others.
Disaster RecoveryIf office server crashes, all data is safe in Azure. New server can sync back from Azure instantly.

🏢 Real Company Scenarios — Azure Files

Infosys has 300,000+ employees across 50 offices in India. Each project team shares configuration files, code templates, and documentation. Instead of email attachments or USB drives, they mount an Azure File Share on every developer's laptop. All 10 developers on a team work on the same config files. When a senior engineer updates a config file from Pune, the developer in Bengaluru sees it immediately — no manual sync needed.

A Hospital Chain (example: Fortis) uses Azure File Sync across 28 hospitals. Medical reports, doctor notes, and billing templates are stored in Azure Files. Each hospital's server syncs locally for fast access. If the Mumbai hospital server crashes, doctors can still access all patient files from Azure directly within minutes.

MakeMyTrip runs 20 web servers behind a load balancer. All 20 servers need the same app.config, SSL certificates, and static HTML templates. Storing these on each server separately means 20 manual updates every time something changes. Solution: mount one Azure File Share on all 20 servers. Update the config once — all 20 servers use it immediately.

06 · NoSQL Storage

Azure Table Storage

Azure Table Storage is a NoSQL key-value store for storing structured data. It stores billions of rows cheaply without needing a full SQL database setup.

Simple Analogy
Azure Tables is like a giant Excel sheet in the cloud. Each row is an entity (a student record). Each column is a property (Name, Age, Grade). You can store billions of rows and find any row instantly using a key.

Key Concepts

TermMeaningExample
TableA collection of entitiesStudentTable
EntityA single record (one row)Sahil's record
PropertyA field/columnName, Age, City
Partition KeyGroups related entities for fast queriesCity = "Delhi"
Row KeyUnique ID within a partitionRollNumber = "2021CS01"
🏢 Real Company Scenarios — Azure Tables

Ola stores driver location updates in Azure Tables. Every 5 seconds, 500,000 active drivers send their GPS coordinates. That's 100 million writes per hour. Azure Tables handles this cheaply — much cheaper than SQL Server for this type of high-volume, simple data. Partition Key = city (Delhi, Mumbai), Row Key = driverID. Query "all Delhi drivers" instantly.

IoT Smart Meter company (like Tata Power smart meters) — each meter sends electricity readings every 15 minutes. With 1 million meters, that's 4 million rows per hour. Azure Tables stores all readings. Users query: "show readings for meter 12345 in July 2026" — instant result using PartitionKey=MeterID, RowKey=Timestamp.

Azure Tables vs Azure SQL Database
Azure Tables is NoSQL — no JOINs, no complex queries, but extremely fast and cheap for simple lookups. Use Tables for high-volume simple data (IoT, logs, user preferences). Use Azure SQL Database when you need complex queries, relationships between tables, and transactions.

07 · Message Queue

Azure Queue Storage

Azure Queue Storage stores messages between application components. One part of the app adds a message to the queue; another part reads and processes it. This creates asynchronous, decoupled communication.

Simple Analogy
Imagine a restaurant kitchen display system. A waiter takes your order and puts a ticket on the screen. The chef reads tickets one by one. The waiter doesn't stand in the kitchen waiting — they go take more orders. Queue Storage works exactly like this for applications.

Why Message Queues?

Problem Without QueueSolution With Queue
Web app freezes while processing a large orderApp adds order to queue and responds immediately. Background worker processes it.
If email service is down, emails are lostMessage stays in queue until email service comes back up — no data loss
10,000 requests per second crash the backendAll 10,000 messages wait in queue. Backend processes at its own capacity.
Worker crashes mid-processingMessage becomes visible again in queue after lock expires. Another worker picks it up.
Key Technical Facts
• Max message size: 64 KB
• Max queue size: 500 TB
• Message expiry (default): 7 days
• Visibility timeout: Message locked while worker processes. If worker crashes, lock expires (30 sec default) and another worker gets it.
🏢 Real Company Scenarios — Queue Storage

Swiggy Order Pipeline — when you place a food order, the app doesn't process everything at once. The checkout service adds a message to Queue: "OrderID: 98765, Items: [Biryani x2], Restaurant: ABC". The app immediately responds "Order Placed!" to you. Behind the scenes, separate workers read from the queue: Worker 1 notifies the restaurant, Worker 2 processes payment, Worker 3 assigns a delivery partner. Each is independent — if the payment service is slow, the restaurant notification still happens on time.

Paytm OTP Pipeline — when you request OTP, the web service doesn't call the SMS provider directly (that's slow and risky). It adds a message to a queue: "Send OTP 457823 to +91-9876543210". An SMS worker reads from the queue and calls the SMS provider. If the SMS provider API is temporarily down, the message stays in queue and is retried automatically — you get the OTP once the provider is back up.

08 · Redundancy

Storage Redundancy Types

Azure automatically keeps multiple copies of your data to protect against hardware failures. The redundancy type determines where copies are kept and how many.

Simple Analogy
Redundancy is like making photocopies of your marksheet. LRS = 3 copies in one building. GRS = 3 copies in Delhi + 3 copies in Mumbai (in case Delhi floods). More copies = more safety = more cost.
LRS
Locally Redundant Storage

3 copies within one datacenter in one region. Cheapest option. Survives disk/rack failure but not datacenter failure.

ZRS
Zone Redundant Storage

3 copies across 3 Availability Zones in same region. Survives full zone outage.

GRS
Geo-Redundant Storage

3 copies in primary region + 3 copies in paired region (e.g., Central India → South India). Survives region-wide disaster.

GZRS
Geo-Zone Redundant

3 zone copies in primary + 3 in paired region. Maximum protection against both zone and region failures.

TypeCopiesSurvivesCostWhen to Use
LRS3Disk/rack failureCheapestDev/test, non-critical data
ZRS3Zone outageMediumHigh availability apps in one region
GRS6Regional disasterHigherBusiness-critical data, compliance
GZRS6Zone + Region failureHighestMaximum durability, banking, healthcare
🏢 Real Company — Choosing Redundancy

ICICI Bank uses different redundancy for different data. Internal test database → LRS (cheapest, doesn't matter if it's lost). Core banking transaction logs → GRS (copies in Central India + South India — RBI compliance requirement for disaster recovery). Customer-facing loan documents → GZRS (maximum protection — losing these would violate regulations).

10 · Cloud Comparison

Azure Storage vs AWS Equivalents

Storage TypeAzure ServiceAWS EquivalentKey Difference
Object Storage Blob Storage Amazon S3 Azure uses "Containers"; AWS uses "Buckets". Both store files via URL.
Block Storage Azure Managed Disks Amazon EBS Azure auto-manages storage accounts. AWS EBS needs manual snapshot management.
File Storage (SMB/NFS) Azure Files Amazon EFS Azure Files supports both SMB (Windows) + NFS (Linux). EFS supports NFS only.

Why Know Both?
Most IT companies in India use both AWS and Azure (multi-cloud strategy). Wipro, Infosys, TCS, HCL all have clients on both clouds. Knowing both makes you more employable and lets you answer interview questions comparing the two.
11 · Summary

Chapter Summary

3 Storage Types — The Most Important Concept

  • Block Storage (Managed Disks) = VM's hard drive. Attached directly. Use for OS, databases. AWS EBS equivalent.
  • Object Storage (Blob) = Files accessed via URL. Use for images, videos, backups. AWS S3 equivalent.
  • File Storage (Azure Files) = Shared network drive. Mounted by multiple VMs. AWS EFS equivalent.

Key Points to Remember

  • Azure Storage has 5 services: Blob, Managed Disks, Files, Tables, Queue
  • Storage Account must be created first for Blob/Files/Tables/Queue — NOT required for Managed Disks
  • Storage Account name is globally unique and becomes part of the URL
  • Managed Disks: Ultra > Premium SSD v2 > Premium SSD > Standard SSD > Standard HDD (cost vs performance)
  • Disk Roles: OS Disk (required) + Data Disk (optional) + Temp Disk (DO NOT store data — not persistent!)
  • Azure Files supports SMB (Windows/Linux) and NFS (Linux only). Can be mounted as a drive letter.
  • Azure File Sync = sync on-premises Windows Servers with Azure Files (cloud tiering = free up local disk)
  • Blob Access Tiers: Hot → Cool → Cold → Archive (cheaper storage, slower access)
  • SAS Token = temporary URL for private blobs with expiry time
  • Redundancy: LRS (cheapest) → ZRS → GRS → GZRS (maximum protection)
  • Container access: Private by default. Blob or Container level for public access.
