Lab 1 of 5
1
Create a Storage Account
The foundation — everything lives inside this
What We Are Doing
Creating a Storage Account is like opening a new bank account. Without it, you cannot store anything in Azure Storage.
  • 1
    Open the Azure Portal and log in
    portal.azure.com → Sign in with your Azure account
  • 2
    Search for Storage accounts in the top search bar
    Search bar → "storage accounts" → Click first result
  • 3
    Click + Create to start creating a new storage account
  • 4
    Fill in the Basics tab:
    Settings
    Resource Group   : [select your existing group]
Storage name     : iimt2026storage  # must be lowercase, globally unique
Region           : Central India
Performance      : Standard
Redundancy       : LRS  # cheapest, fine for practice
  • 5
    Click Review + Create → then Create
    Wait ~30 seconds for deployment to complete
  • 6
    Click Go to resource once deployment is done — this opens your Storage Account
Expected Result
You should see the Storage Account overview page. The URL will be: https://iimt2026storage.blob.core.windows.net

Lab 2 of 5
2
Blob Storage — Upload a File
Create a container and upload a file — access via URL
What We Are Doing
We will create a Blob Container (like a folder) and upload a file. Then we'll see what happens when we try to open the file's URL without permission.
  • 1
    Inside your Storage Account → Left menu → Containers
    Storage Account → Data storage → Containers
  • 2
    Click + Container to create a new container
    Set Name: student-files
    Set Public access level: Private (no anonymous access)
    Click Create
  • 3
    Click on the container student-files → Click Upload
  • 4
    Upload any file from your laptop (image, PDF, etc.) → Click Upload
  • 5
    Click on the uploaded file → Click Copy URL
  • 6
    Paste the URL in a new browser tab and press Enter
    You should get a 403 ResourceNotFound error — this is correct! The container is Private.
Why 403 Error?
The container is set to Private. No one can access blobs without authorization. This is the correct and secure default. In the next lab we will generate a temporary URL (SAS Token) to share the file.

Lab 3 of 5
3
Generate a SAS Token
Create a temporary URL that expires — share files safely
What We Are Doing
SAS = Shared Access Signature. It generates a special URL with a secret key and expiry time. After the time expires, the URL stops working — perfect for temporary sharing.
  • 1
    Click on the uploaded file inside student-files container
  • 2
    Click Generate SAS tab (in the top menu of the file)
  • 3
    Fill in SAS settings:
    SAS Settings
    Signing method    : Account key
Permissions       : Read  # only read, not write or delete
Start time        : Now (default)
Expiry time       : +2 hours from now
Allowed protocols : HTTPS only
  • 4
    Click Generate SAS token and URL
  • 5
    Copy the Blob SAS URL (the full URL with the ?sv=... part)
  • 6
    Paste this URL in a new browser tab — the file should now open/download successfully!
Show Students This
Wait for the expiry time to pass (or set it to 1 minute for demo). Try the URL again after expiry — it will give a 403 error again. This shows how SAS Token provides time-limited, secure access.

Lab 4 of 5
4
Create Azure File Share
A shared network folder in the cloud (SMB)
What We Are Doing
We will create a File Share — a shared drive that multiple VMs can access simultaneously, like a company's common Z: drive.
  • 1
    Go back to your Storage Account → Left menu → File shares
    Storage Account → Data storage → File shares
  • 2
    Click + File share
    Name: classshare
    Tier: Transaction optimized
    Click Create
  • 3
    Click on classshare → Click Upload → Upload any file from your laptop
  • 4
    Click Connect (top menu) → Select Windows tab
    You will see a PowerShell script that mounts this share as a drive on Windows.
  • 5
    Copy the PowerShell script — it looks like this:
    PowerShell
    $connectTestResult = Test-NetConnection -ComputerName iimt2026storage.file.core.windows.net -Port 445
if ($connectTestResult.TcpTestSucceeded) {
    # Mount drive
    cmd /c "net use Z: \\iimt2026storage.file.core.windows.net\classshare /u:AZURE\iimt2026storage [storage-key]"
}
Expected Result
After creating, you should see classshare listed under File shares. In the next lab, we mount this on a VM.

Lab 5 of 5
5
Mount File Share on a Windows VM
Connect the cloud drive as Z: inside a virtual machine
What We Are Doing
We will RDP into a Windows VM and run the PowerShell script from Lab 4 to mount the Azure File Share as a Z: drive inside the VM.
  • 1
    Go to your Windows VM → Click Connect → RDP
    Download the .rdp file and open it → Log in with your VM credentials
  • 2
    Inside the VM → Open PowerShell as Administrator
    Start → Right-click PowerShell → Run as Administrator
  • 3
    Paste and run the PowerShell script you copied from Lab 4, Step 5
  • 4
    Open File Explorer → Look under This PC → You should see a Z: drive!
  • 5
    Open the Z: drive → You will see the file you uploaded in Lab 4 → Open it
    Now try copying a new file into Z: — it appears in Azure Portal too!
Classroom Demo Tip
Open the Azure Portal and the Z: drive side by side on screen. Upload a file to Z: from the VM — refresh the portal — students will see it appear in real time. This demonstrates that the Z: drive IS the Azure cloud storage.
What You Proved
✅ Azure File Share works exactly like a local network drive
✅ Any file saved to Z: is instantly stored in Azure cloud
✅ Multiple VMs in the same region can mount the same share
